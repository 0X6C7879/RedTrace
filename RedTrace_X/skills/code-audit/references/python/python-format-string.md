# 格式化字符串漏洞

## 0. 黄金法则

> **漏洞存在性判断 优先于 防护有效性判断**
>
> 固定格式字符串 = 无 格式化字符串漏洞（这是漏洞本质判断，不是防护有效判断）
>
> 满足此条件时：立即终止分析，无需检查任何防护措施。

**强制执行顺序**：
1. **首先**：区分格式字符串 vs 格式变量
2. **然后**：确认格式字符串是否用户可控
3. **仅当** 格式字符串用户可控时，才检查防护
4. **禁止**：一上来就检查"有没有白名单"

---

## 1. 结论判断标准

| 结论 | 定义 | 判定条件 |
|------|------|----------|
| **漏洞** | 用户输入可作为格式字符串，可泄露信息或执行代码 | 格式字符串用户可控 + HTTP 入口 + 无防护 |
| **风险-A** | 危险格式化但无 HTTP 入口可达 | 危险操作 + 无外部入口 |
| **风险-B** | 有入口但仅信息泄露 | HTTP 入口可达 + 仅泄露信息无代码执行 |
| **安全** | 固定格式字符串 / 白名单上下文 / 类型约束 | 格式字符串固定 / f-string / 白名单 |

---

## 2. 研判思路

### 2.1 研判流程

```
Step 1: 格式化操作识别 【终止点】
  ├─ 固定格式字符串（如 "Hello {}" / f-string）？ → 安全（终止）
  ├─ 用户可控格式字符串？ → 继续
  └─ 未发现格式化操作？ → 安全（终止）

Step 2: 用户可控性检查（关键区分） 【终止点】
  ├─ 格式字符串来自常量？ → 安全（终止）
  ├─ 仅变量值来自用户（格式字符串固定）？ → 安全（终止）
  └─ 格式字符串本身来自用户输入 → 继续

Step 3: 防护措施检查
  ├─ 白名单上下文（ALLOWED_VARS）？ → 安全（终止）
  ├─ 类型约束（int() 转换）？ → 安全（终止）
  └─ 无防护 → 继续

Step 4: HTTP 入口可达性 【终止点】
  ├─ 无 HTTP 入口？ → 风险-A
  ├─ 有 HTTP 入口且可代码执行？ → 漏洞
  └─ 有 HTTP 入口但仅信息泄露？ → 风险-B
```

### 2.2 降级条件表

| 条件 | 原结论 | 降级后 |
|------|--------|--------|
| 固定格式字符串 | 漏洞 | 安全 |
| 仅变量值来自用户 | 漏洞 | 安全 |
| f-string 表达式 | 漏洞 | 安全 |
| 白名单上下文 | 漏洞 | 安全 |
| 类型约束 | 漏洞 | 安全 |
| 无 HTTP 入口 | 漏洞 | 风险-A |

## 3. 常见漏洞/风险场景

### 漏洞

```python
# 用户控制格式字符串
fmt = request.args.get('format')
return fmt.format(**locals())  # 漏洞：可访问 locals()

# % 格式化
user_format = request.args.get('fmt')
return user_format % locals()  # 漏洞

# logging.basicConfig 用户可控格式
logging.basicConfig(format=user_input)  # 漏洞
```

### 安全（常见误报排除）

```python
# 固定格式字符串
"Hello {}".format(name)  # 安全

# f-string
f"Hello {name}"  # 安全

# 仅变量值来自用户
template = "Hello {}"
return template.format(user_input)  # 安全
```

---

## 4. 常见防御模式

```python
# 固定格式字符串
"Hello {}".format(name)  # 安全

# 白名单上下文
ALLOWED_VARS = {'name', 'email'}
return fmt.format(**{k: v for k, v in locals().items() if k in ALLOWED_VARS})  # 安全

# 类型约束
return "{:d}".format(int(user_input))  # 安全
```

## 6. 常见误判场景

### 陷阱1：混淆格式字符串和变量值

**错误**: 看到 .format(user_input) 就判为漏洞
**正确**: 格式字符串固定，仅变量值来自用户 → 安全

### 陷阱2：f-string 误判

**错误**: 看到 f-string 就判为漏洞
**正确**: f-string 的表达式在编译时确定，非用户可控 → 安全

### 陷阱3：日志格式化误判

**错误**: 看到 `logging.info("msg: %s", var)` 就判为漏洞
**正确**: 这是安全的日志参数化写法，格式字符串固定

---

## 7. 特殊风险

### logging.basicConfig 格式注入

`logging.basicConfig(format=user_input)` 中若 format 来自用户输入，可利用格式化占位符泄露程序状态信息。虽不能直接执行代码，但可泄露 `%(filename)s`、`%(module)s` 等内部信息。
