# 开放重定向案例集

> 整合内部真实漏洞与业界经典案例，提供实战指导

## 一、内部真实案例

### 案例1：某内部系统URL跳转风险（短链服务）
**描述**: 获取短链接接口未对传入的长链接域名做检查，可传入任意地址的长链接，短链接的访问接口会重定向到此长链接，存在任意URL跳转问题。由于访问短链接携带公司域名，存在一定迷惑性，可用于钓鱼攻击。

**修复建议**: 检查传入长链接域名的合法性，建议使用白名单进行限制。

**经验总结**: 重定向目标URL需使用白名单校验，而非黑名单过滤，确保只跳转到已知安全的域名

---

### 案例2：某内部系统任意URL跳转
**描述**: 某内部系统获取的identiId不重要，不依赖此鉴权。重定向目标缺乏域名合法性校验，可跳转至任意外部地址。

**修复建议**: 设置白名单检查redirectUrl，仅限跳转到特定域名上，禁止跳转到任意域名。

**经验总结**: 相对路径重定向要注意`//example.com`这种可被当作协议相对URL的情况

---

### 案例3：海外分享通用中间页服务存在任意地址跳转（可用于欺诈钓鱼）
**描述**: 该接口中的url参数缺乏限制，可以指定任意url地址，并重定向到任意地址。由于是分享中间页，携带公司官方域名，迷惑性强，可用于欺诈钓鱼。

**修复建议**: 对url进行限制，只能是我方允许的域名。

**经验总结**: OAuth回调地址需严格匹配注册时的URL，不能使用前缀匹配或正则宽松匹配

---

### 案例4：存在任意URL跳转漏洞（ticket验证绕过）
**描述**: 存在任意url跳转漏洞，但存在ticket验证，只有在ticket过期前才可以成功跳转。ticket验证时间窗口内仍可利用，需关注ticket有效期长度。

**修复建议**: 在ticket校验的基础上同时校验重定向目标域名白名单。

**经验总结**: 开放重定向常被用作钓鱼攻击的跳板，需评估重定向参数的必要性

---

### 案例5：某内部系统存在任意URL跳转漏洞（sourceUrl参数）
**描述**: 某内部系统存在任意URL跳转漏洞，通过修改sourceUrl参数值为恶意第三方网站，由于站点未对跳转的url进行校验，由于是公司的网站比较信任，导致未开通的账户或者已开通小店的账户，在点击关闭功能点后，导致跳转至第三方恶意网站，造成安全隐患，例如被钓鱼。

**修复建议**: 对sourceUrl参数添加域名白名单校验，拒绝非白名单域名的跳转请求。

**经验总结**: 对重定向URL进行解码后再校验，防止URL编码绕过检测

---

### 案例6：某内部系统登出处CSRF及URL重定向漏洞
**描述**: 存在两处问题：1、登出处CSRF漏洞：因为没有进行referer校验，该登出接口可被CSRF利用，用户访问恶意网站后会将当前浏览器中的账号登出；2、URL重定向：可以指定任意一个跳转地址，可用于网络钓鱼攻击。

**修复建议**: 1、CSRF：增加referer检查；2、URL重定向：限制可跳转的目标，进行followUrl的检查。

**经验总结**: 内部系统的链接跳转如果包含用户可控的URL参数，同样需要校验目标域名

---

### 案例7：CasLoginFilter存在任意URL跳转、敏感Cookie未设置httponly
**描述**: 此过滤器中存在两个问题：1、redirectUrl参数未检查域名是否为预期域名，存在任意url跳转；2、返回的x-auth-token httponly属性未设置为true，若存在xss漏洞则可获取用户x-auth-token。

**修复建议**: 1、检查redirectUrl是否为预期域名；2、返回的cookie设置httponly为true。

**经验总结**: 移动端深链（Deep Link）的目标URL需要校验，防止跳转到恶意地址

---

### 案例8：某内部系统 /security/link 存在任意URL跳转
**描述**: 此链接是跳转到站外链接时请求的，构造url参数可指向任意外部地址。由于接口本身为公司安全域名下，用户对链接信任度高，被钓鱼的概率更大。

**修复建议**: 从url中解析出实际跳转的域名，再进行白名单判断。

**经验总结**: JavaScript的location.href赋值如果使用用户输入，需校验协议和域名

---

### 案例9：某内部系统存在任意地址跳转漏洞（gameScheme参数）
**描述**: /developer/api/qrcode 接口会根据参数gameScheme进行重定向，gameScheme缺乏安全性校验，可以重定向到任意地址，需要添加白名单限制，仅允许重定向到白名单允许的地址。

**修复建议**: 添加白名单校验，限制gameScheme参数只能为已注册的游戏scheme值。

**经验总结**: 短链服务需校验原始URL的目标域名，防止被滥用为重定向跳板

---

### 案例10：短链服务缺陷导致任意URL跳转
**描述**: /compress接口可根据传入的原始url，返回短链。但是由于对原始链接合法性的检测存在缺陷，导致检测失效。配合访问短链可重定向到原始链接接口，可形成任意url跳转问题。根因在于使用了contains()进行域名检测，导致bypass。

**修复建议**: 不使用contains()。建议使用URL()，把原始url生成url对象，提取host，使用equals()精确比较host是否是可信域名。

**经验总结**: 登录后重定向的returnUrl参数需严格校验，这是最常见的开放重定向场景

---

## 三、方法论总结

### 3.1 高频参数统计

| 参数名 | 出现频次 | 说明 |
|--------|----------|------|
| `url` | 4次 | 最直接的重定向目标参数，常见于中间页、短链服务 |
| `redirectUrl` / `redirect_url` | 2次 | 登录/认证流程中的回调跳转参数 |
| `sourceUrl` | 1次 | 来源页面跳转参数，操作完成后返回 |
| `followUrl` | 1次 | 登出后的跟随跳转参数 |
| `gameScheme` | 1次 | 游戏应用的scheme跳转参数 |
| `returnUrl` / `return` | 通用 | 登录成功后的returnUrl，开放重定向最高发场景 |

### 3.2 攻击模式分布

| 攻击模式 | 案例数量 | 典型场景 |
|----------|----------|----------|
| 短链服务被滥用为跳板 | 2个 | 短链生成接口域名校验缺陷、短链跳转无域名限制 |
| 分享/中间页任意跳转 | 1个 | 海外分享通用中间页url参数无限制 |
| 登录/认证流程中的重定向 | 2个 | CasLoginFilter的redirectUrl、ticket验证后跳转 |
| 操作后回跳参数被劫持 | 2个 | sourceUrl关闭按钮跳转、followUrl登出后跳转 |
| 内部安全链接跳转 | 1个 | /security/link站外跳转无域名校验 |
| 游戏/应用Scheme跳转 | 1个 | gameScheme参数重定向任意地址 |
| 域名校验逻辑缺陷（contains绕过） | 1个 | 使用字符串contains()校验被绕过 |
| 协议相对URL绕过 | 1个（场景） | //evil.com被解析为协议相对URL |

### 3.3 关键检测信号

**接口特征**:
- 响应状态码为 `301`、`302`、`303`、`307`、`308` 的跳转接口
- 接口参数名含有 `url`、`redirect`、`return`、`next`、`to`、`target`、`link`、`jump`、`goto` 等语义
- 短链生成/访问接口（包含原始URL参数）
- OAuth/SSO登录回调接口（含 `redirect_uri`、`callback`、`state` 参数）
- 应用内中间页/分享落地页接口

**响应特征**:
- `Location` 响应头指向请求参数中传入的外部域名
- `meta refresh` 或 JavaScript `location.href` 跳转目标为用户输入值
- 响应体中的跳转链接域名与当前站点域名不同

**代码审计信号**:
- 使用 `String.contains()`、`String.startsWith()` 校验域名（可被 `evil.example.com.evil.com` 绕过）
- 未使用 `URL()` / `URI` 对象解析后提取 `host` 属性进行精确比较
- 重定向前未 URL 解码（导致编码绕过）
- 允许 `//` 开头的相对协议URL跳转
- 允许 `javascript:`、`data:` 等危险协议作为跳转目标

### 3.4 常见绕过技巧

| 绕过技巧 | 适用场景 | 原理与要点 |
|----------|----------|------------|
| 协议相对URL（`//evil.com`） | 仅校验`/`开头相对路径 | 浏览器将`//evil.com`解析为`https://evil.com`，绕过以`/`判断相对路径的检测 |
| 子域名混淆（`example.com.evil.com`） | `contains("example.com")`校验 | 目标域名包含合法域名字符串，骗过字符串包含检测 |
| URL编码（`%68%74%74%70`） | 校验前未解码 | `http://evil.com`编码后绕过对明文URL的关键词过滤 |
| 双重URL编码（`%2568%2574%2574%2570`） | 单次解码后校验 | 服务端仅做一次decode，二次编码后绕过过滤 |
| 路径穿越结合重定向（`/safe/../../redirect`） | 白名单路径前缀校验 | 通过`..`使最终路径脱离白名单前缀范围 |
| `@`符号混淆（`http://trusted.com@evil.com`） | URL解析不当 | 浏览器将`@`前视为用户名，实际跳转到evil.com |
| 空白字符插入（`http://evil.com\t`） | 简单字符串匹配 | Tab/换行符在某些解析器中被忽略 |
| `javascript:` 伪协议 | 无协议白名单校验 | 跳转执行JS代码，可结合XSS使用 |
| 参数污染（`?url=trusted.com&url=evil.com`） | 取第一个参数校验 | 服务端校验第一个url参数，实际使用第二个值跳转 |
| 短链叠加（短链指向短链） | 短链服务校验当前层 | 生成指向另一个短链服务的短链，绕过单层域名校验 |
