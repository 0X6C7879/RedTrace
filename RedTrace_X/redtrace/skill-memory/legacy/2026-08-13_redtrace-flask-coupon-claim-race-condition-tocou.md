# 并发竞态绕过「每人限领一张」优惠券限制

## 场景
Flask（Werkzeug 开发服务器，多线程）电商秒杀/优惠券 Web 应用，登录仅需用户名（无密码）。
领取优惠券接口存在 check-then-act 竞态（TOCTOU）：先查询当前用户是否已领取，未领取才插入新优惠券，两步非原子且无唯一约束/锁。

## 验证方法
1. 登录任意用户名获得 session cookie。
2. 用同一 session 并发 POST /claim_coupon（50~60 线程），多数请求都成功领取到优惠券（如 60 请求成功 27~34 张，面值 10~100 随机）。
3. 领取到的多张优惠券可在购买结算时多选叠加抵扣（/purchase 支持 coupon_ids 数组），凑够高价商品金额即可 0 元购买 flag 商品。

## 关键结论
- 单次正常领取第二张会返回「每人限领一张」失败；并发即可绕过。
- 竞态收益：并发请求数与成功数近似成正比，一次 60 并发即可稳定凑够 999 面值。
- 抵扣逻辑为 max(0, price - sum(coupon_values))，多张可叠加。
- 修复方向：领取前对 user_id 加唯一约束（DB unique index）或事务内 SELECT ... FOR UPDATE / 原子 upsert / 分布式锁。

## 复用要点
- 通用竞态领取 + 凑额购买脚本模式：login → 并发 claim → 读券 → 按面值贪心选取到 >= 目标价 → POST 购买。
- 面值随机 10~100，目标价越高需越多次并发；失败重试即可（每次领取独立）。
