# 普通计算任务的事件合并模拟

这是封闭的本地模拟实验：Step 计算数字的平方，Fact 保存计算结果。脚本没有模块导出、Agent、外部工具或生产运行时依赖。

运行规格中的全部验收用例：

```sh
rtk proxy /opt/homebrew/opt/node@24/bin/node experiments/task-wake-simulation/simulation.mjs
rtk proxy /opt/homebrew/opt/node@24/bin/node experiments/task-wake-simulation/simulation.mjs null
```

参数为正整数 Step 上限或 `null`（无上限）。省略时使用 `3`，对应实现时核对的项目配置 `tasks.reason.max_intents`；此值是实验默认快照，后续配置变化需通过参数传入。脚本不读取运行时配置或凭证。

## 唤醒合同

- 按任务累计 Fact 和成功／失败结束事件，两者可以来自不同 Step，顺序不限。正常规划同时要求两类事件未被处理、尚有容量且没有规划正在运行。
- 待执行、执行中和暂停 Step 都占容量。取消只释放容量，不产生结束事件；重复设置同一终态不会重复计数。
- 首次启动允许规划一次。停止、完成以及人工重新激活只更新图状态，不能单独满足唤醒条件；重新激活保留已有事件。
- 规划开始时固定事件边界，成功后确认该边界。规划期间到达的事件留给下一轮，旧的结束事件不能与未来的 Fact 重复配对。
- 规划失败保留事件。模拟调用方传入重试截止时间，脚本仅检查资格，不定义新的退避策略、轮询或定时器。
- 满容量保留事件；尾阶段有空闲容量仍不能仅因 Fact 到达而规划。规划使用有限且不重复的有效计算候选，能补满则补满，没有更多候选时允许不饱和。

图修订号独立记录 Fact、Step 和任务状态变化；规划资格只使用事件边界与容量。图更新可立即被读取，不受规划门槛影响。

## 恢复与实验边界

验收通过 JSON 序列化／恢复验证未处理事件和确认边界。中断的规划恢复为待重试，不能误确认其事件。无上限用 `null` 保存，恢复后仍有效。

这个实验验证调度语义，尚未提供实际磁盘持久化、界面通知、生产调度或真实计算执行器；所有事件由验收用例显式推进。生产代码与提示词不属于本实验的交付范围。
