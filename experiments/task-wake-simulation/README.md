# 普通计算任务的事件合并模拟

这是封闭的本地模拟实验：起点是一组待验证整数，Goal 是取得它们的平方结果，Subgoal 是验证单个整数，Step 执行平方计算，Fact 保存结果，Finding 保存多个结果的合计。脚本没有模块导出、真实 Agent、外部工具或生产运行时依赖。

运行脚本内的全部验收用例：

```sh
rtk proxy /opt/homebrew/opt/node@24/bin/node experiments/task-wake-simulation/simulation.mjs
rtk proxy /opt/homebrew/opt/node@24/bin/node experiments/task-wake-simulation/simulation.mjs null
```

参数为正整数 Step 上限或 `null`（无上限），省略时使用实验默认值 3。脚本不读取生产配置、凭证或数据库。

## 唤醒与事件确认

- 首次规划允许启动一次。之后任一有效 Fact、Finding、Step 成功或失败事件都允许规划，无须等待另一类事件或空余 Step 容量。
- 每个任务最多一个规划活动。规划期间的新增事件只更新一个简短提醒，提醒包含最新事件序号，不附带完整图；模拟调用方显式取出提醒并读取增量。
- 增量读取按事件序号分页，区分已读取、已评估和已确认边界。读取或收取提醒不能确认事件；成功结束才确认已评估边界。
- 结束检查和确认在同一个同步函数内完成。仍有未评估事件时返回继续当前规划，补读和评估后再结束；提交结束之后到达的事件由下一轮处理。
- Step 容量只限制创建任务。待执行、执行中、暂停和等待停止确认的 Step 都占容量；满容量仍允许规划及取消、替换。
- 计划创建、编辑、取消、Goal/Subgoal 更新不产生规划通知，避免规划自我循环。成功或失败终态重复提交不重复计数。
- 调用方可传入逻辑时间截止值；提醒不延长截止时间。失败、停止或预算耗尽保留未确认事件，并使用调用方传入的重试时间。没有新增定时器、轮询或自动重试执行器。

## Step 与目标调整

- Step 引用起点或本任务的有效 Fact/Finding，绑定匹配且开放的 Subgoal；有限候选集合之外的计算、明确重复的活动计算和已验证计算被拒绝。
- 尚未执行的 Step 可以原地修改输入、Subgoal 和来源。运行中或暂停后的内容修改进入等待停止状态，保留旧执行；明确确认停止后才创建替代 Step，再由模拟调用方显式启动。
- 调整优先级无需停止。删除表示退出有效计划并保留历史；正在运行的被删除 Step 在停止确认前仍占容量。旧执行进入停止状态后的迟到结果被拒绝。
- Subgoal 可以修改描述、取消或凭匹配证据达成。关闭目标停止对应活动 Step；已关闭的目标不允许启动替代任务。Step 成功结束本身不表示目标达成。
- 根 Goal 达成要求证据覆盖全部候选输入，可以引用 Fact 或引用它们的 Finding；达成后关闭剩余分支并停止活动 Step。

## 提交质量

- Fact 必须来自当前运行的计算，提供非空证据说明和目标价值说明，结果须与本地整数平方一致；不接受超出安全整数范围的输入或结果。
- 同一输入和结果的重复 Fact 返回已有节点，不改图修订、不产生事件。提交内容不能覆盖系统生成的身份和归属字段。
- Finding 必须引用至少两个不同的有效 Fact，并给出正确、安全的结果合计及目标价值说明；相同支持集合与相同合计视为重复，引用顺序和说明改写不会增加事件。
- 证据文字与价值文字只是提交者自审声明，代码额外验证的是这个算术实验中的结果、引用和目标关联。这里没有语义审核模型，不能据此声称可以识别任意自然语言的无价值或近义重复内容。

## 恢复与实验边界

脚本内置 29 项断言验收，覆盖事件合并、增量分页、结束边界、预算、重复拒绝、目标证据、停止后替换、迟到提交、容量、失败恢复和任务隔离。JSON 恢复保留事件及确认边界，中断规划恢复为待重试，停止中的替代请求也被保留。

所有事件、评估、逻辑时间和停止确认由验收用例显式推进；评估只是有限平方候选的确定性模拟。同步结束边界和 JSON 往返验证不代表真实跨进程原子性、磁盘持久化、模型提醒或执行器取消已实现。本次修改限于模拟脚本和本说明，没有连接生产调度或自主攻击流程。

工作区中的生产合同测试 `packages/redtrace-engine/test/wake-contract.test.ts` 是独立改动，不随本实验更新；不能依据本实验验收推断生产合同已经符合此处的新语义。

## SQLite 查询验证

`sqlite-query-check.mjs` 使用 Node 内置 SQLite 和内存数据库，比较全量读取／解析与单点读取加 Step／Goal 筛选。数据只有本地平方结果，不导入生产引擎，不启动执行器，不访问现有数据库。

```sh
rtk proxy /opt/homebrew/opt/node@24/bin/node experiments/task-wake-simulation/sqlite-query-check.mjs
```

脚本覆盖 123／20,083 个节点和 1／8 个读取者，断言两种查询结果相同、任务隔离正确、筛选查询及单点查询命中索引。输出包含每种读法的节点解析数、9 次采样的耗时／CPU 时间中位数和查询计划；耗时仅供比较，不作为固定验收阈值。该实验仍然读取全部历史 Step／Goal，数量增长时成本也会增长。

本次运行结果保存在 `sqlite-query-results.json`。这是封闭实验的对比值，不是生产延迟指标；生产热路径另由 `scheduler-hot-path.test.ts` 验证 20,083 节点下 dispatch 不调用 `graph()`，并检查实际查询命中 `(project_id, kind)` 索引。
