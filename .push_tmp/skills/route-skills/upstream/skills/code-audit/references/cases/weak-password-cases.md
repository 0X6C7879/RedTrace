# 弱口令与暴力破解案例集

> 整合内部真实漏洞与业界经典案例，提供实战指导

## 一、内部真实案例

### 案例1：某内部系统登录接口存在暴力破解问题
**系统**: 某内部系统

**漏洞描述**:
某内部系统登录接口存在暴力破解问题。白帽子通过暴力破解猜到了部分用户名和密码，进而登入了平台。平台包含用户反馈和用户管理两个功能，用户管理模块含有邮箱信息及脱敏手机号。被扫到的弱口令系外部用户自行修改所设，平台生成的初始密码为8位随机字符串。

**技术细节**:
- 登录接口缺乏失败次数限制和账号锁定机制
- 验证码机制缺失或强度不足，无法有效阻止自动化暴力破解
- 用户可将系统生成的强随机密码修改为弱口令，且无密码强度校验
- 属于"接口速率无限制 + 用户自选弱口令"的组合风险

**修复方案**:
登录接口增加短信验证码，或在连续失败N次后触发账号临时锁定/滑块验证，防止自动化暴力破解。

**经验总结**:
默认密码必须在首次登录时强制修改，系统不应允许使用出厂默认凭证。

### 案例2：财务RPA系统NAS弱口令导致读取敏感文件并RCE
**系统**: 某内部系统

**漏洞描述**:
财务 RPA 系统的 NAS 存储使用弱口令。攻击者登录 NAS 后，可获取机器人流程代码，进而：1）代码中包含访问敏感对账数据的接口和凭证，导致未授权访问 C4 级敏感数据；2）可在机器人脚本目录中植入恶意脚本，当机器人执行核对流程时调用，触发远程代码执行（RCE）。

**技术细节**:
- NAS 密码为弱口令，包含公司品牌关键词或简单数字组合
- NAS 存储了含有内部 API 凭证的机器人脚本，凭证未加密存储
- 机器人执行时直接加载 NAS 目录中的脚本，缺乏脚本签名或完整性校验
- 弱口令 → 敏感数据泄露 + RCE 的完整攻击链

**修复方案**:
立即修改 NAS 密码为强口令：禁止含公司品牌关键词、`ks` 等关键词，要求大小写字母、数字及特殊字符组合，长度不低于8位，且不与其他账户共享。

**经验总结**:
密码强度策略需在服务端强制执行，不能仅依赖前端校验。

### 案例3：k-tag系统可以被暴力破解账号密码
**系统**: 某内部系统

**漏洞描述**:
k-tag 系统登录模块的验证码可被自动化程序识别，导致验证码机制失效。同时，可固定密码对账号进行批量枚举，从而破解弱口令账号。外网域名 `k-tag.kwai.com` 同样存在相同问题。

**技术细节**:
- 验证码可被 OCR 等自动化工具识别，无法有效阻止机器登录
- 登录接口无频率限制，允许无限次尝试
- 攻击者可采用"固定密码，枚举账号"策略批量爆破
- 系统同时在内外网暴露，外网攻击面更广

**修复方案**:
强化验证码（使用行为验证或图形复杂度更高的验证码），同时对登录接口实施访问频率限制（如同一 IP 或同一账号每分钟最多5次失败尝试）。

**经验总结**:
登录接口需限制失败尝试次数，超过阈值后实施账号锁定或验证码机制。

### 案例4：12台服务器远程管理卡使用默认口令
**系统**: 某内部系统

**漏洞描述**:
12台服务器的远程管理卡（IPMI/BMC）使用默认口令，可被攻击者登录并获取服务器管理权限。可执行操作包括查看服务器状态、开关机、重装系统、通过 VNC 远程连接服务器等高危操作。

**技术细节**:
- 远程管理卡出厂默认凭证从未被修改
- BMC/IPMI 默认口令通常为厂商公开的 `admin/admin`、`ADMIN/ADMIN` 等
- 远程管理卡独立于操作系统运行，绕过 OS 层安全策略
- 12台主机同时暴露，攻击者可批量接管服务器

**修复方案**:
立即修改所有远程管理卡密码为强口令，建立管理卡凭证统一管理机制，并将管理卡网络隔离至独立管理 VLAN。

**经验总结**:
API 密钥、Token 等凭证不应硬编码在代码或配置文件中，需使用密钥管理服务。

### 案例5：nettrix网络设备弱口令（多台）
**系统**: 某内部系统

**漏洞描述**:
两个团队交接机器时，新团队多人共用同一设备，BMC 版本需要经常刷新，刷新后未及时修改密码，导致反复出现弱口令问题。多台网络设备受影响。

**技术细节**:
- 设备在版本刷新后密码被重置为默认值，无自动化提醒或强制修改流程
- 多人共享凭证，无法追溯操作行为
- 团队交接流程未包含安全凭证的交接和重置步骤
- 属于"流程缺失导致的配置安全问题"

**修复方案**:
设置强口令，建立设备凭证生命周期管理规范：版本刷新后强制触发密码修改流程，团队交接时必须重置所有凭证，禁止多人共享凭证。

**经验总结**:
内部管理系统的默认账号密码需在上线前修改，并建立定期轮换机制。

### 案例6：admin用户弱密码可控制1万+IDC机器实例
**系统**: 某内部系统

**漏洞描述**:
`admin` 用户存在弱密码，可通过该账号控制超过1万台 IDC 机器实例。影响范围极大，属于高危漏洞（此工单仅做记录，若密码已修改可直接确认修复）。

**技术细节**:
- 核心管理账号 `admin` 使用弱密码，如 `admin123`、`123456` 等常见口令
- 该账号权限级别极高，可操作大规模 IDC 基础设施
- 弱密码可在短时间内被字典攻击破解
- 单点凭证泄露影响整个 IDC 机器池

**修复方案**:
立即修改 `admin` 用户密码为高强度随机密码，同时启用多因素认证（MFA），对 admin 账号的所有操作记录审计日志。

**经验总结**:
暴力破解防护需考虑分布式攻击，单 IP 限速不够，需结合账号维度的限速。

### 案例7：Kubesphere弱口令
**系统**: 某内部系统

**漏洞描述**:
Kubernetes 管理平台 KubeSphere 在多个节点（172.29.81.251/252/253）存在弱口令问题，可导致攻击者获取容器编排平台的管理权限，进而控制其上运行的所有容器和服务。

**技术细节**:
- KubeSphere 控制台使用弱口令，初始化后未强制修改
- KubeSphere 拥有创建/删除 Pod、访问 Secret（含数据库密码等凭证）等高权限
- 容器平台被攻破后，可横向移动至平台上的所有服务
- 多个节点使用相同弱口令，密码复用加大影响范围

**修复方案**:
修改 KubeSphere 管理密码为强口令，启用 RBAC 最小权限原则，限制 KubeSphere 控制台的网络访问范围至内网特定 IP 段。

**经验总结**:
密码重置流程中的验证码/链接需有较短的有效期，且只能使用一次。

### 案例8：Jenkins弱口令导致执行系统命令
**系统**: 某内部系统

**漏洞描述**:
Jenkins 账号密码相同（弱口令），登录后可通过 Jenkins Script Console 执行任意系统命令，威胁个人电脑及 CI/CD 流水线安全，同时存在被劫持钓鱼的风险。

**技术细节**:
- Jenkins 账号密码均为弱口令（如 `admin/admin`、`jenkins/jenkins`）
- Jenkins 内置 Groovy Script Console 允许执行任意系统命令（`"cmd".execute()`）
- 攻击者可通过 Script Console 植入后门、窃取 CI/CD 密钥、篡改构建产物
- Jenkins 通常拥有源码仓库访问权限，危害可扩大至代码供应链

**修复方案**:
修改 Jenkins 为强口令，禁用 Script Console 或限制其访问权限至管理员角色，启用基于矩阵的授权策略（Matrix-based security）实施最小权限原则。

**经验总结**:
使用弱哈希算法（MD5/SHA1）存储密码极易被彩虹表破解，应使用 bcrypt/argon2。

### 案例9：个人邮箱账号弱密码
**系统**: 某内部系统

**漏洞描述**:
邮箱账号使用弱密码，可被暴力猜解。恶意攻击者成功猜解账号后，可访问公司邮箱系统及 Docs 等内部协作平台，造成敏感信息泄露。

**技术细节**:
- 用户邮箱密码使用连贯字母或数字组合（如 `123456`、`qwerty`、姓名拼音等）
- 邮箱系统无登录失败限制，可进行字典爆破
- 邮箱关联多个内部系统（Docs、OA 等），一旦被攻击影响面广
- 属于"用户安全意识不足 + 系统缺乏密码复杂度约束"的组合问题

**修复方案**:
更改为高强度密码，不使用连贯字母及数字。同时邮件系统应强制执行密码复杂度策略，并启用多因素认证。

**经验总结**:
测试环境的弱口令账号不应出现在生产环境，需做好环境隔离。

### 案例10：用户账号密码登录接口存在暴力破解
**系统**: 某内部系统

**漏洞描述**:
`/rest/v1/qarth/user/login` 接口在验证账号和密码时没有进行次数限制，可对账号密码进行暴力破解。攻击者可利用此接口批量尝试常见密码，获取弱口令用户的登录凭证。

**技术细节**:
- 登录接口未接入风控系统，无频率限制、无账号锁定、无验证码保护
- 接口可无限次调用，支持自动化脚本批量爆破
- 结合用户名枚举漏洞（如注册时的提示信息），可高效确定有效账号
- 属于典型的"接口速率限制缺失"漏洞

**修复方案**:
接入风控系统，或对该接口进行次数限制（如同一账号5分钟内失败超过5次则触发验证码或临时锁定）。

**经验总结**:
批量账号注册时需限速和验证码，防止攻击者批量创建账号进行暴力破解。

## 二、业界经典案例（乌云）

### 案例1：借前人经验沦陷某省1400万流动人口信息（OA弱口令）
**厂商**: 某省 OA 系统 | **类型**: 后台弱口令（导致数据泄露）

**洞察**: OA 系统使用默认弱口令，登录后可访问1400万条流动人口信息，弱口令的危害级别与泄露数据规模直接相关。

**测试流程**:
1. 发现 LQL_OA 登录页面
2. 尝试 `admin/123456`、`admin/admin` 等常见弱口令
3. 成功登录后访问人员信息管理模块
4. 批量导出或访问敏感数据

**技术细节**:
`http://IP:8888/LQL_OA/login.aspx` 使用前人经验的弱口令登录，获取1400万条流动人口数据。

**POC示例**:
```
常用弱口令组合测试:
admin/123456
admin/admin
admin/888888
admin/Admin123
```

**绕过技巧**: 无验证码限制，暴力破解可行

**修复建议**: 强制修改默认密码，密码策略要求至少8位含大小写和数字，添加登录失败锁定机制

## 三、方法论总结

### 3.1 高频参数统计

| 弱口令类型 | 出现频次 | 典型场景 |
|------------|----------|----------|
| `admin/admin` | 6次 | OA 系统、农机系统、安全设备、工控后台 |
| `admin/123456` | 4次 | OA 系统、通用 Web 后台 |
| `weblogic/weblogic` | 2次 | Java EE 中间件管理控制台 |
| `admin/123` | 1次 | 电网管理系统 |
| 账号密码相同 | 3次 | Jenkins、KubeSphere、k-tag |
| 含品牌名/服务名 | 3次 | `公司品牌名`、`jenkins`、`weblogic` |
| 数字递增序列 | 4次 | `123456`、`12345678`、`123` |

### 3.2 攻击模式分布

| 攻击模式 | 案例数 | 典型案例 |
|----------|--------|----------|
| **默认凭证未修改** | 6个 | 服务器管理卡、KubeSphere、Weblogic、农机系统、安全设备 |
| **暴力破解（无防护）** | 4个 | 登录接口无限制、验证码可被 OCR 识别、邮箱系统 |
| **弱口令 + 二次漏洞利用** | 4个 | 弱口令 → RCE（Jenkins Script Console）、弱口令 → 文件上传、弱口令 → WAR 部署 |
| **密码复用跨系统** | 2个 | 58同城多站点、多设备共享密码 |
| **工控/物联网弱口令** | 3个 | 电网系统、农机调度、NAS（财务RPA） |
| **高权限账号弱口令** | 3个 | admin 控制 1万+IDC 主机、宽带推送、发改委 |

### 3.3 关键检测信号

1. **登录接口速率限制**：检查接口是否存在失败次数限制、账号锁定机制、验证码触发策略
2. **默认凭证**：测试 `admin/admin`、`admin/123456`、`服务名/服务名`（weblogic、jenkins等）等常见默认凭证
3. **验证码有效性**：检查图形验证码是否可被 OCR 程序自动识别，行为验证码是否可被绕过
4. **基础设施管理界面**：BMC/IPMI、Weblogic 控制台、Jenkins Script Console、KubeSphere、ZooKeeper 等是否可从外网访问
5. **密码复杂度策略**：注册/修改密码接口是否在服务端强制校验密码复杂度要求
6. **弱口令后续危害**：登录后检查是否存在代码执行能力（Script Console）、文件上传、敏感数据导出等高危功能
7. **多系统密码复用**：同一弱口令是否在多个子系统中通用（批量爆破）

### 3.4 常见绕过技巧

1. **OCR 识别验证码**：使用 OCR 库（Tesseract 等）自动识别图形验证码，绕过验证码防护
2. **分布式低频暴力破解**：使用多个 IP 地址低频请求，绕过单 IP 速率限制（需结合账号维度限速）
3. **固定密码枚举账号**：使用 `123456`、`password` 等超高频弱口令，枚举有效账号列表
4. **默认凭证数据库**：使用 Shodan、FOFA 搜索暴露的管理面板，结合已知默认凭证字典尝试登录
5. **密码喷洒（Password Spraying）**：一个密码测试所有账号，规避账号锁定策略
6. **凭证填充（Credential Stuffing）**：使用历史数据泄露中的账号密码对目标系统进行批量撞库
7. **弱口令跨系统横向**：在一处发现弱口令后，尝试相同凭证登录同一组织的其他系统（密码复用）
