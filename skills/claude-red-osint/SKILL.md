# Claude Red: OSINT

Use this Skill to collect attributable public evidence and turn it into bounded security hypotheses.

## Workflow

1. Define the entity, purpose, jurisdictions, allowed sources, time window, personal-data limits, and stop conditions.
2. Read [offensive-osint.md](references/offensive-osint.md) and select only the relevant collection and correlation sections.
3. Begin with high-confidence identifiers, then pivot through independently attributable relationships.
4. Preserve source URL, retrieval time, search terms, and enough context to reproduce the observation.
5. Corroborate material claims with an independent source or direct technical evidence.
6. Minimize retained personal data and distinguish observed facts, inferred relationships, stale records, and unresolved hypotheses.

## Tool readiness

Check required commands before use. If a tool is missing, follow RedTrace's common missing-tool bootstrap: search official documentation or releases online, choose an OS/architecture-compatible user-local installation, verify its checksum or provenance and run a version/smoke check, then reuse it. Do not guess command syntax, loop on installation, or block the assessment when a bounded fallback exists.

## Validation standard

Require source attribution and reproducible correlation. Name similarity, cached search snippets, autogenerated profiles, and a single stale record do not establish ownership or current exposure.

## Safety boundary

Use public or explicitly authorized sources only. Do not impersonate people, purchase illicit data, evade access controls, harass individuals, or retain unrelated sensitive information.
