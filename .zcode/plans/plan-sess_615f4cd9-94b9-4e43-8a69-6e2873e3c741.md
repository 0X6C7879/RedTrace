## Skill Memory 目录重构 — 实施方案

### 概述

将 Skill Memory 从中央 `.redtrace/skill-memory/` 迁移到每个 Skill 自身目录下的 `memory/`，同时修复 loaded-skill tracking 语义问题。涉及 6 个源文件 + 4 个测试文件 + 1 个 SKILL.md + .gitignore。

---

### 1. `skill_cli.py` — 路径改为 per-skill

**`_memory_dir(skills_dir, name)`** — 签名增加 `name` 参数：

```python
def _memory_dir(skills_dir: Path, name: str) -> Path:
    override = _env("REDTRACE_SKILL_MEMORY_DIR")
    if override:
        return Path(override).resolve() / name
    return skills_dir / name / "memory"
```

- 默认：`skills/<name>/memory/`
- Override：`$REDTRACE_SKILL_MEMORY_DIR/<name>/`

**`learn()`**：
- `memory = _memory_dir(skills)` → `memory = _memory_dir(skills, name)`
- `path = memory / f"{name}.jsonl"` → `path = memory / "records.jsonl"`
- `audit_path = memory / "audit.jsonl"` — 保持不变（现在是 per-skill audit）
- `_lock(memory)` — 现在锁在 `skills/<name>/memory/.lock`（per-skill 独立锁）

**`recall()`**：
- `memory = _memory_dir(skills)` → `memory = _memory_dir(skills, name)`
- `records = _read_records(memory / f"{name}.jsonl")` → `records = _read_records(memory / "records.jsonl")`

**`_legacy_notes(memory, name, limit)`** — 不变。`memory / "legacy"` 现在解析为 `skills/<name>/memory/legacy/`，迁移后只含与该 Skill 匹配的 legacy notes。关键词过滤逻辑保留（幂等、无害）。

**`_bundled_note(skills, name)`** — 不变（已经 per-skill，读 `skills/<name>/learned/learned.md`）。

---

### 2. `agent_runtime.py` — 迁移逻辑 + 移除默认 env

**`_ensure_skill_memory()`** — 替换为一次性幂等迁移：

```python
def _ensure_skill_memory(self) -> None:
    """Migrate legacy Skill Memory into per-skill memory directories.

    Old central layout → new per-skill layout:
      managed/skill-memory/<name>.jsonl      → skills/<name>/memory/records.jsonl
      managed/skill-memory/audit.jsonl      → skills/<name>/memory/audit.jsonl (split by skill)
      managed/skill-memory/legacy/*.md       → skills/<name>/memory/legacy/*.md (by keyword match)
      skills/.redtrace/learning/<name>.jsonl → skills/<name>/memory/records.jsonl

    Notes matching no skill → skills/_legacy-unmatched/.
    Old sources preserved (not deleted). Idempotent: copy/merge only if not present.
    """
```

迁移逻辑流程：
1. 遍历 `skills/` 中所有含 `SKILL.md` 的目录（不区分 enabled/disabled）
2. 对每个 Skill `<name>`：
   - 创建 `skills/<name>/memory/`
   - 从旧源 `managed/skill-memory/<name>.jsonl` 和 `skills/.redtrace/learning/<name>.jsonl` 合并 records 到 `skills/<name>/memory/records.jsonl`（按 digest 去重，cap 100 条）
   - 从旧中央 `managed/skill-memory/audit.jsonl` 筛选 `skill == <name>` 的条目，合并到 `skills/<name>/memory/audit.jsonl`（按 digest 去重，cap 1000 条）
3. 分发 legacy notes：
   - 遍历 `redtrace/skill-memory/legacy/*.md`（bundled）和 `managed/skill-memory/legacy/*.md`（runtime copy）
   - 对每条 note，用与 `_legacy_notes` 完全相同的匹配逻辑（`terms = {skill_name, skill_name.replace("-", " ")}`）检查匹配哪些 Skill
   - 匹配的 Skill：复制到 `skills/<name>/memory/legacy/`（目标已存在则跳过）
   - 不匹配任何 Skill：复制到 `skills/_legacy-unmatched/`（目标已存在则跳过）
   - 生成 `skills/_legacy-unmatched/MIGRATION.md` 报告：列出每条 note 分发到了哪些 Skill 或被标记为 unmatched

新增模块级辅助函数：
- `_read_jsonl(path) -> list[dict]` — 读 JSONL（skip malformed lines）
- `_write_jsonl(path, records)` — 原子写 JSONL（用 `atomic_write_text`）
- `_merge_jsonl_by_digest(source, target, cap)` — 按 digest 去重合并
- `_merge_audit_by_skill(source, target, skill_name, cap)` — 按 skill 字段过滤 + digest 去重
- `_distribute_legacy_notes(source_legacy, skills_with_names, unmatched_dir)` — 分发 legacy notes

删除 `_copy_missing_tree()`（不再使用）。

**`_initialize_worker()`** — 移除默认 `REDTRACE_SKILL_MEMORY_DIR`：

```python
# 删除这段：
"REDTRACE_SKILL_MEMORY_DIR": (
    str(self.paths.managed / "skill-memory")
    if self.execution == "local"
    else "/opt/redtrace/skill-memory"
),
```

用户显式在 redtrace.yaml 中设置时仍然生效（来自 config 的 `worker.env` 不被覆盖）。未设置时，`skill_cli.py` 的 `_memory_dir` 使用默认 `skills/<name>/memory/`。

---

### 3. `containers.py` — 移除 skill-memory 挂载

删除 `_shared_volumes()` 中的：

```python
self._host_source(self._paths.managed / "skill-memory"): {
    "bind": "/opt/redtrace/skill-memory",
    "mode": "rw",
},
```

`skills/` 已经以 rw 挂载到 `/opt/redtrace/claude-plugin/skills`，`skills/<name>/memory/` 直接可写。

---

### 4. `common.py` — 修复 tracking 语义

**移除 `_seed_loaded_skills` 调用**：

```python
# 原来：
if tracking_path is not None:
    process_env["REDTRACE_LOADED_SKILLS_FILE"] = str(tracking_path)
    _seed_loaded_skills(tracking_path, process_env.get("REDTRACE_SKILL_PATHS", ""))

# 改为：
if tracking_path is not None:
    process_env["REDTRACE_LOADED_SKILLS_FILE"] = str(tracking_path)
```

tracking 文件不再在 task 开始时预填所有 exposed Skills。只有 Agent 显式调用 `redtrace-skill track-load <skill>` 才会记录。`learn()` 保持 fail-closed：未记录为 loaded 的 Skill 被拒绝。

**删除函数**：`_seed_loaded_skills`（不再调用）和 `_read_loaded_skills`（从未被调用，dead code）。

**保留**：`resolve_skill_tracking_path`、`_cleanup_skill_tracking`、`cleanup_skill_tracking`（tracking 生命周期不变）。

**保留** reason-task env stripping 中的 `REDTRACE_SKILL_MEMORY_DIR`（`pop(name, None)` 对不存在的 key 是 no-op，且用户显式设置时仍需被 strip）。

---

### 5. `skills/skill-evolution/SKILL.md` — 更新 learning 流程

当前 SKILL.md 描述 "只有本次被 Runtime 记录为已加载的专业 Skill 才能写入经验"。Runtime 不再自动预填 tracking，需要更新：

- 在"写入经验"步骤前增加 `track-load` 指引：对本次任务中**实际加载并使用过**的专业 Skill，先运行 `redtrace-skill track-load <canonical-id>` 记录加载
- 更新"写入目标"中的措辞：从"被 Runtime 记录为已加载"改为"本次实际加载并通过 track-load 记录"
- `learn()` 的 fail-closed 语义保持不变

---

### 6. `.gitignore`

增加 per-skill memory 运行时锁目录：
```
# Per-skill memory runtime lock (ephemeral, created by learn())
skills/*/memory/.lock/
```

不添加 `records.jsonl` 或 `audit.jsonl` 的 ignore — 它们应该被 Git 跟踪。

---

### 验收清单

| # | 要求 | 实现 |
|---|------|------|
| 1 | Memory 默认与 Skill 共存 | `_memory_dir` 默认 `skills/<name>/memory/` |
| 2 | Memory 全部 Git 可跟踪 | `.gitignore` 只忽略 `.lock/`，不忽略 `.jsonl` |
| 3 | 每个 Skill 独立 Memory/Audit/锁 | per-skill `_memory_dir` + per-skill `_lock` |
| 4 | `REDTRACE_SKILL_MEMORY_DIR` 只作 override | `_initialize_worker` 不设默认值 |
| 5 | 默认不创建 `managed/skill-memory` | 迁移只读取旧源，不创建新目录 |
| 6 | 默认不挂载 `/opt/redtrace/skill-memory` | `containers.py` 删除 bind mount |
| 7 | 旧 Memory 自动幂等无损迁移 | `_ensure_skill_memory` digest 去重 + 存在检查 |
| 8 | recall 只读 Memory | `recall()` 不变，不调 `_track_skill_load` |
| 9 | learn 仍 fail-closed | `learn()` 不变 |
| 10 | tracking = 实际加载的 Skill | 移除 `_seed_loaded_skills`，只有 `track-load` 记录 |
| 11 | 不增 Learning Session/Hook/LLM 调用 | 只删逻辑，不加新机制 |
| 12 | 测试更新、行为不回归 | 4 个测试文件更新 |

7. 测试文件更新（4 个）
